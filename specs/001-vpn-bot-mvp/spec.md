# Feature Specification: vpn-bot-mvp

**Feature Branch**: `[001-vpn-bot-mvp]`  
**Created**: 2026-07-31  
**Status**: Draft  
**Input**: User description: Telegram-бот для продажи доступа к резидентскому VPN. Доступ продается пакетами трафика...

## Clarifications

### Session 2026-08-04
- Q: Как происходит подтверждение оплаты клиентом? → A: Клиент должен перевести фиксированную сумму и отправить скриншот (фото) чека в бота. Бот пересылает фото администратору с инфой о заказе.
- Q: Как реализована авторизация в Marzban API? → A: OAuth2PasswordBearer, получение токена через POST `/api/admin/token` (`application/x-www-form-urlencoded`) используя `MARZBAN_USERNAME` и `MARZBAN_PASSWORD` из `.env`. Токен автоматически обновляется.
- Q: Где находится контракт для Marzban API? → A: В файле `docs/marzban_openapi.json`, он используется как источник истины для API-клиента и DTO-моделей.
- Q: Создает ли администратор профили вручную? → A: Нет, флоу строго автоматизирован. Хэндлер вызывает Use Case, который автоматически обращается к Marzban API, создает профиль, сохраняет его в БД и отправляет клиенту ссылку.
- Q: Какие переменные окружения обязательны? → A: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_ID`, `MARZBAN_API_URL`, `MARZBAN_USERNAME`, `MARZBAN_PASSWORD`.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Выбор и покупка пакета (Priority: P1)

Как клиент, я хочу видеть приветственное сообщение, главное меню и возможность выбрать один из тарифов для покупки (50 ГБ - 130 руб, 150 ГБ - 250 руб, 450 ГБ - 449 руб). Я хочу иметь возможность оплатить тариф, отправить боту скриншот (фото) чека, чтобы подтвердить перевод.

**Why this priority**: Это основной бизнес-поток привлечения клиентов и совершения продаж.
**Independent Test**: Можно полностью протестировать флоу взаимодействия бота с клиентом до отправки заявки со скриншотом администратору.

**Acceptance Scenarios**:

1. **Given** новый пользователь вызывает бота, **When** он отправляет команду `/start`, **Then** бот присылает приветствие и главное меню (Купить VPN, Моя подписка, Поддержка).
2. **Given** пользователь в главном меню, **When** он нажимает "Купить VPN", **Then** бот отображает список доступных тарифов.
3. **Given** список тарифов, **When** пользователь нажимает на выбранный тариф, **Then** бот присылает реквизиты для перевода средств и просит отправить фото чека.
4. **Given** пользователь получил реквизиты, **When** он отправляет фото чека, **Then** бот сообщает, что заявка отправлена, и формирует уведомление администратору с прикрепленным фото.

---

### User Story 2 - Подтверждение заявки администратором (Priority: P1)

Как администратор, я хочу получать уведомления о новых заявках в свой Telegram. Под заявкой должны быть inline-кнопки "Подтвердить" / "Отклонить". Администратор НЕ создает профили вручную. При подтверждении хэндлер должен вызвать сервисный класс (Use Case), который автоматически создаст профиль через Marzban API и обновит статус заявки.

**Why this priority**: Без подтверждения заявки клиент не получит VPN. Автоматизация экономит время администратора и снижает риск человеческой ошибки.
**Independent Test**: Заявку можно симулировать в базе, проверив уведомление и обработку нажатия кнопки админом, убедившись, что Use Case успешно вызывает API и отправляет сообщение.

**Acceptance Scenarios**:

1. **Given** пользователь отправил фото чека, **When** заявка сохранена, **Then** администратор получает сообщение с фото чека, деталями заявки и кнопками "Подтвердить"/"Отклонить".
2. **Given** заявка ожидает подтверждения, **When** администратор нажимает "Подтвердить", **Then** вызывается Use Case, который обращается к Marzban API для создания пользователя, сохраняет данные в VPNProfile и отправляет клиенту `subscription_url`.
3. **Given** заявка ожидает подтверждения, **When** администратор нажимает "Отклонить", **Then** бот отклоняет заявку и уведомляет клиента об отказе.

---

### User Story 3 - Получение доступа клиентом (Priority: P1)

Как клиент, после подтверждения оплаты администратором, я хочу автоматически получить сообщение с моей индивидуальной VLESS-ссылкой (subscription_url) и инструкцией по настройке.

**Why this priority**: Предоставление непосредственной ценности клиенту после успешной продажи.
**Independent Test**: Изолированный тест отправки правильного сообщения с подставленными ссылками клиенту.

**Acceptance Scenarios**:

1. **Given** администратор нажал "Подтвердить", **When** профиль в Marzban успешно создан, **Then** бот немедленно отправляет клиенту сообщение с VLESS-ссылкой и инструкцией.

---

### User Story 4 - Проверка остатка трафика (Priority: P2)

Как клиент, я хочу проверять остаток трафика через кнопку "Моя подписка". Бот должен запрашивать актуальный `used_traffic` и `data_limit` из Marzban и показывать остаток в гигабайтах.

**Why this priority**: Важная фича для удержания пользователей и информирования, но не блокирует первичную продажу MVP.
**Independent Test**: Тест функции вычисления `data_limit - used_traffic` на основе mock-данных от Marzban.

**Acceptance Scenarios**:

1. **Given** клиент с активным профилем, **When** он нажимает "Моя подписка", **Then** бот делает запрос в Marzban, высчитывает остаток и выводит его в формате "Осталось: X.X ГБ".

---

### Edge Cases

- What happens when клиент нажимает "Я оплатил" несколько раз подряд? (Система должна блокировать спам заявок, разрешая только одну активную неоплаченную заявку).
- How does system handle ошибку API Marzban при подтверждении заявки админом (например, таймаут)? (Администратору должно прийти сообщение об ошибке, а заявка остается в статусе "ожидает", чтобы можно было повторить попытку позже).
- What happens when клиент запрашивает статус подписки, но его профиль отсутствует в Marzban? (Бот сообщает клиенту, что активной подписки не найдено, и предлагает купить пакет).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST отображать главное меню с кнопками "Купить VPN", "Моя подписка", "Поддержка".
- **FR-002**: Система MUST предлагать тарифы: 50 ГБ (130 руб), 150 ГБ (250 руб), 450 ГБ (449 руб).
- **FR-003**: Система MUST выдавать реквизиты для оплаты и ожидать от пользователя отправки скриншота (фотографии) чека для фиксации заявки.
- **FR-004**: Система MUST пересылать фото чека администратору с деталями заказа и inline-кнопками для подтверждения или отклонения заявки.
- **FR-005**: Система MUST обращаться к REST API Marzban (с использованием OAuth2PasswordBearer и автообновлением токена) при подтверждении заявки администратором.
- **FR-006**: Система MUST создавать пользователей в Marzban с параметрами: `data_limit_reset_strategy: "no_reset"`, `expire: null`, и лимитом в соответствии с выбранным пакетом.
- **FR-007**: Система MUST автоматически отправлять клиенту его `subscription_url` и инструкции после успешного создания профиля в Marzban.
- **FR-008**: Система MUST запрашивать у Marzban API значения `used_traffic` и `data_limit` для профиля клиента и выводить остаток трафика при запросе статуса.
- **FR-009**: Система MUST ограничивать возможности администратора только для заранее заданного ID.

### Key Entities

- **User**: Telegram-пользователь (содержит ID, username).
- **Order**: Заявка на покупку (ID пользователя, выбранный пакет, статус: pending, approved, rejected, дата создания).
- **Package**: Пакет трафика (лимит в гигабайтах/байтах, цена в рублях).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% заявок доходят до администратора без потери данных.
- **SC-002**: При подтверждении заявки пользователь получает ссылку доступа в течение 10 секунд (с учетом задержек Telegram и API Marzban).
- **SC-003**: Клиенты получают точный расчет остатка трафика (округление до сотых долей ГБ).
- **SC-004**: Бот способен выдержать пиковую нагрузку в 50 одновременных пользователей, отправляющих команды (обеспечивается асинхронностью).

## Assumptions

- Обязательные переменные окружения заданы в `.env`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_ID`, `MARZBAN_API_URL`, `MARZBAN_USERNAME`, `MARZBAN_PASSWORD`. Панель управления для админов не требуется.
- REST API Marzban работает корректно и доступен боту по сети. Авторизация происходит по логину и паролю (`MARZBAN_USERNAME`, `MARZBAN_PASSWORD` из `.env`) через POST `/api/admin/token` (`application/x-www-form-urlencoded`).
- OpenAPI спецификация `docs/marzban_openapi.json` является актуальной и используется как единственный источник истины для кодогенерации или написания API-клиента и DTO-моделей.
- Курс и цены зафиксированы жестко (согласно требованиям), динамическое управление ценами не реализовано в MVP.
- Реквизиты для оплаты и тексты инструкций являются статическими параметрами, заданными в конфигурации.
