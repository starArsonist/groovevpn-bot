# Feature Specification: connect-links

**Feature Branch**: `feature/connect-links` (spec dir: `specs/003-connect-links`)  
**Created**: 2026-10-06  
**Status**: Draft (ожидает подтверждения перед implement)  
**Input**: User description: подключение подписки в один тап - кнопки, которые открывают приложение и сами добавляют подписку.

## Clarifications

### Session 2026-10-06 (решения владельца)

- Q: Какую проблему решаем? → A: После выдачи подписки пользователь вручную копирует ссылку и вставляет в приложение. Нужны кнопки, которые открывают приложение и добавляют подписку сами.
- Q: Как кнопка бота открывает приложение? → A: Bot API не принимает кастомные URL-схемы в URL-кнопке (проверено, см. research.md), поэтому кнопка ведёт на https-страницу-прослойку, а страница перенаправляет на deeplink приложения.
- Q: Какие приложения и схемы? → A: `happ://add/<URL подписки>`, `v2raytun://import/<URL подписки>`, `hiddify://import/<URL подписки>#<имя профиля>`.
- Q: Как передаются данные на страницу? → A: Во фрагменте URL: `https://<страница>/#app=happ&sub=<percent-encoded URL подписки>`. Фрагмент не уходит на сервер, токен подписки не попадает в логи хостинга.
- Q: Как защититься от open redirect и подстановки чужих подписок? → A: Страница принимает только приложения из белого списка и только https-подписки с хостом из `ALLOWED_SUB_HOSTS` (по умолчанию пусто = отказ; хост пропишет владелец при деплое). Всё из фрагмента выводится только через `textContent`/DOM API.
- Q: Где показывать кнопки? → A: При первой выдаче подписки (триал и первая оплаченная покупка) и на экране с данными подписки («Моя подписка»; экран уже есть, нового пункта меню не нужно). При продлении существующей подписки кнопки не навязываем.
- Q: Что если страница не настроена? → A: Бот работает как раньше (ссылка текстом), в логе предупреждение; падать нельзя.
- Q: Деплой? → A: Не входит в задачу: только описание в README.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Подключить подписку одним тапом после выдачи (Priority: P1)

Пользователь получает сообщение со ссылкой подписки и под ним кнопки приложений. Он нажимает кнопку своего приложения, открывается страница, которая запускает приложение и добавляет подписку.

**Why this priority**: Это вся ценность фичи: убрать ручное копирование и вставку.

**Independent Test**: С настроенным `CONNECT_PAGE_URL` выдать триал и подтвердить первую покупку через фейковый Marzban; проверить, что в сообщении есть кнопки приложений в заданном порядке, URL каждой кнопки - страница с корректным фрагментом, ссылка в `<code>` экранирована.

**Acceptance Scenarios**:

1. **Given** настроена страница и пользователь получил триал, **When** бот отправляет сообщение с выдачей, **Then** под ссылкой подписки (в `<code>`) идут кнопки приложений в порядке `CONNECT_APPS`, ниже остальные действия и «Поддержка».
2. **Given** настроена страница и подтверждена первая оплаченная покупка, **When** бот отправляет сообщение, **Then** кнопки приложений и «Поддержка» присутствуют.
3. **Given** подтверждено продление существующей подписки (в том числе покупка триал-пользователем, обновляющая существующего пользователя), **When** бот отправляет сообщение, **Then** кнопок приложений в нём нет.
4. **Given** пользователь повторно нажал «Попробовать бесплатно» при активном триале (бот показывает ту же ссылку), **When** бот отвечает, **Then** кнопки приложений тоже показаны.
5. **Given** ссылка подписки содержит символы `&`, `<`, `>`, **When** сообщение формируется, **Then** ссылка корректно экранирована в HTML и копируется одним тапом.

---

### User Story 2 - Страница-прослойка безопасно открывает приложение (Priority: P1)

Страница по фрагменту URL проверяет данные и запускает deeplink выбранного приложения; рядом показывает крупную кнопку «Открыть в <приложении>», кнопку копирования ссылки и подсказку.

**Why this priority**: Без страницы кнопки бота не работают, а небезопасная страница - вектор атаки (open redirect, подстановка чужой подписки, XSS).

**Independent Test**: Проверка логики валидации через `node --test` без зависимостей; статическая проверка файла на отсутствие внешних запросов и небезопасных API.

**Acceptance Scenarios**:

1. **Given** допустимое приложение и https-подписка с хостом из `ALLOWED_SUB_HOSTS`, **When** страница загружена, **Then** через небольшую задержку выполняется переход на deeplink и показана кнопка «Открыть в <приложении>» с тем же deeplink.
2. **Given** хост подписки не входит в `ALLOWED_SUB_HOSTS` (или список пуст), **When** страница загружена, **Then** нейтральное сообщение об ошибке и никакого редиректа.
3. **Given** неизвестное приложение, пустой фрагмент, `javascript:`/`http:`/`data:` в `sub`, URL с учётными данными или с фрагментом, **When** страница загружена, **Then** нейтральная ошибка без редиректа.
4. **Given** deeplink не открылся, **When** пользователь нажимает «Скопировать ссылку подписки», **Then** ссылка копируется (через `navigator.clipboard`, при отказе - через выделение текста), страница показывает подсказку про установку приложения и открытие в браузере из Telegram.
5. **Given** любой фрагмент, **When** страница отображает данные, **Then** значения выводятся только через `textContent`/DOM API, внешних запросов нет.

---

### User Story 3 - Кнопки на экране «Моя подписка» (Priority: P2)

Пользователь, который открыл «Моя подписка» позже, видит ту же ссылку и кнопки приложений.

**Independent Test**: Вызов обработчика «Моя подписка» с настроенной страницей: кнопки на месте; без настройки - как раньше.

**Acceptance Scenarios**:

1. **Given** есть профиль и страница настроена, **When** пользователь открывает «Моя подписка», **Then** над кнопками «Продлить / докупить», «Назад», «Поддержка» показаны кнопки приложений.
2. **Given** ссылка подписки с HTML-спецсимволами, **When** экран формируется, **Then** ссылка экранирована.

---

### User Story 4 - Бот не зависит от страницы (Priority: P2)

Если `CONNECT_PAGE_URL` пуст или невалиден, бот работает как раньше.

**Independent Test**: Старт с пустым/невалидным значением: кнопок нет, тексты прежние, предупреждение в логе, исключений нет.

**Acceptance Scenarios**:

1. **Given** `CONNECT_PAGE_URL` пуст, не https, без точки в хосте или с пробелами, **When** бот стартует, **Then** кнопки не показываются, ссылка выдаётся текстом, в логе предупреждение.
2. **Given** в `CONNECT_APPS` есть неизвестное приложение, **When** бот стартует, **Then** оно пропускается с предупреждением; если не осталось ни одного - кнопок нет.
3. **Given** Telegram отклонил клавиатуру с кнопками (например, `BUTTON_URL_INVALID`), **When** бот отправляет сообщение со ссылкой, **Then** сообщение отправляется повторно без кнопок приложений, ссылка не теряется.

---

### Edge Cases

- Ссылка подписки очень длинная: URL кнопки превысил бы практический предел Telegram - кнопка для этого приложения пропускается с предупреждением (без вывода URL).
- Приложение не установлено: страница показывает подсказку и ссылку «Где скачать» только для приложений с проверенной официальной страницей.
- Страница открыта во встроенном браузере Telegram: автопереход может блокироваться; подсказка просит открыть страницу в браузере.
- На iOS переход без жеста пользователя может блокироваться: поэтому всегда есть кнопка с тем же deeplink.
- `ALLOWED_SUB_HOSTS` не заполнен при деплое: страница отказывает всем (безопасное поведение по умолчанию).
- Логи бота не должны содержать ни URL подписки, ни полного URL страницы с фрагментом.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Бот MUST читать `CONNECT_PAGE_URL` (по умолчанию пусто) и `CONNECT_APPS` (по умолчанию `happ,v2raytun,hiddify`) из окружения; значения по умолчанию MUST позволять существующему `.env` без этих ключей работать как раньше. Переменные добавляются в `.env.example`.
- **FR-002**: Валидация конфигурации при старте: `CONNECT_PAGE_URL` MUST быть https-адресом с хостом, содержащим точку, без учётных данных и пробелов. При пустом/невалидном значении кнопки MUST NOT показываться, в лог (loguru) пишется предупреждение, бот не падает.
- **FR-003**: Построение URL страницы MUST быть чистой функцией (без сети): `<страница>#app=<app>&sub=<percent-encoded URL подписки>`, порядок приложений из `CONNECT_APPS`, неизвестные приложения отбрасываются.
- **FR-004**: Кнопки приложений MUST показываться: при выдаче триала, при повторном показе ссылки активного триала, при первой оплаченной покупке (включая fallback на создание нового пользователя) и на экране «Моя подписка». При продлении существующей подписки кнопки MUST NOT показываться.
- **FR-005**: Ссылка подписки в сообщениях MUST выводиться в `<code>` с экранированием HTML; под ней inline-кнопки приложений, ниже остальные действия и «Поддержка». Текст короткий, в стиле бота; при отсутствии кнопок остаётся прежний текст с инструкцией.
- **FR-006**: Если Telegram отклоняет сообщение из-за клавиатуры с кнопками приложений, бот MUST повторить отправку без этих кнопок.
- **FR-007**: Бот MUST NOT логировать URL подписки и полный URL страницы с фрагментом; в логи пишется только факт показа кнопок.
- **FR-008**: Страница-прослойка MUST быть одним самодостаточным HTML-файлом без внешних запросов (CDN, шрифты, аналитика, внешние скрипты), с `<meta name="referrer" content="no-referrer">` и `<meta name="robots" content="noindex,nofollow">`.
- **FR-009**: Страница MUST принимать `app` только из белого списка (`happ`, `v2raytun`, `hiddify`) и `sub` только как https-URL без учётных данных и фрагмента, хост которого входит в `ALLOWED_SUB_HOSTS` (константа в начале файла, по умолчанию пустая; при пустом списке - отказ). Иначе нейтральная ошибка без редиректа.
- **FR-010**: Страница MUST выводить данные только через `textContent`/DOM API (не `innerHTML`) и переходить только на схемы из белого списка, собранные по шаблону приложения.
- **FR-011**: Страница MUST через небольшую задержку пробовать открыть deeplink и одновременно показывать крупную кнопку «Открыть в <приложении>», кнопку «Скопировать ссылку подписки» (с запасным вариантом через выделение) и подсказку.
- **FR-012**: Ссылки «Где скачать» на странице MUST вести только на официальные страницы приложений; для приложений без подтверждённой официальной страницы ссылки нет.
- **FR-013**: Текст страницы MUST быть нейтральным, русским, без маркетинга и без слова VPN; светлая/тёмная тема по `prefers-color-scheme`; имя профиля для Hiddify задаётся константой `PROFILE_NAME` (по умолчанию «Groove»).
- **FR-014**: Фича MUST NOT менять схему БД и MUST NOT добавлять Python-зависимости; существующие тесты (перенос остатка, триал) MUST остаться зелёными.

### Key Entities *(include if feature involves data)*

- **Connect config**: настройки подключения (адрес страницы, упорядоченный список приложений); не хранится в БД, читается из окружения при старте.
- **Deeplink приложения**: схема + URL подписки по шаблону приложения; формируется на странице, в боте не хранится.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Подключение подписки в поддерживаемом приложении требует одного нажатия кнопки в боте и (при необходимости) одного нажатия на странице вместо копирования и вставки ссылки.
- **SC-002**: 100% недопустимых сочетаний (чужой хост, неизвестное приложение, `javascript:`, пустой фрагмент, пустой список хостов) завершаются нейтральной ошибкой без редиректа.
- **SC-003**: При пустой или невалидной конфигурации бот стартует и работает без исключений, тексты выдачи подписки идентичны прежним.
- **SC-004**: Ни одно сообщение лога бота не содержит URL подписки или полного URL страницы.
- **SC-005**: Все существующие тесты проекта (86 шт. на baseline) остаются зелёными.

## Assumptions

Предложенные мной решения (ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ, см. отчёт по фазе 0):

- Кнопки показываются и при повторном показе ссылки активного триала, и на экране «Моя подписка» при любом статусе подписки (ссылка там и так показывается).
- Одна кнопка на приложение в отдельной строке, подписи вида «Подключить в Happ».
- При наличии кнопок инструкция сокращается до одной строки; без кнопок остаётся прежняя инструкция.
- Хост на странице сравнивается точно (без суффиксов), порт любой; `sub` с фрагментом, учётными данными или пробелами отклоняется.
- Файл страницы содержит CSP-мета (`default-src 'none'`) как дополнительную защиту от внешних запросов.
- Схемы `happ://add/` и `v2raytun://import/` приняты со слов владельца и проверяются на устройствах (в официальной документации подтверждена только схема Hiddify, см. research.md).
- Деплой страницы, реальное открытие приложений на iOS/Android/Windows/macOS и поведение во встроенном браузере Telegram проверяет владелец на устройствах.
