# Research & Decisions: connect-links

## Как сейчас устроено (проверено по исходникам)

- Ссылка подписки (`subscription_url` из Marzban) хранится в `VPNProfile.sub_url` и показывается пользователю в четырёх местах:
  1. Первая оплаченная покупка: `AdminUseCases._apply_new_purchase` ([admin_use_cases.py](../../src/use_cases/admin_use_cases.py)) - `bot.send_message` с `<code>{html.escape(sub_url)}</code>` и инструкцией по Happ, **без клавиатуры** (кнопки пока нет вообще). Сюда же попадает fallback «пользователь удалён в Marzban (404) -> создаётся новый» - это тоже первая выдача новой ссылки.
  2. Триал: `render_trial_result` ([handlers/trial.py](../../src/adapters/tg_bot/handlers/trial.py)) для `GRANTED` и `ALREADY_ACTIVE` - `<code>` с `html.escape`, клавиатура «Моя подписка / Купить VPN / Поддержка».
  3. Экран «Моя подписка»: `my_subscription_handler` ([handlers/subscription.py](../../src/adapters/tg_bot/handlers/subscription.py)) - `<code>{data['sub_url']}</code>` **без `html.escape`** (найденный дефект: ссылка с `<`/`&` сломала бы разбор HTML и сообщение не отредактировалось бы). Исправляется в рамках фичи (FR-005).
  4. Продление (`_topup_success_message`) - ссылку не показывает и не должен.
- Меню: `/start` -> «Купить VPN», «Моя подписка», «Поддержка» (+ «Попробовать бесплатно»). Экран с данными подписки уже есть («Моя подписка»), поэтому отдельный пункт «Подключиться» **не нужен**.
- Телеграм-текст в проекте - HTML-режим, эмодзи только функциональные, короткий дефис.
- Логирование: `loguru`, уровень INFO в stdout. В коде нет логов с `sub_url`; Marzban-клиент не логирует тела ответов. Нужно сохранить это свойство и закрепить тестом.
- DI: зависимости создаются в `main.py`, кладутся в `bot_data` (хендлеры) или в конструкторы use cases (`AdminUseCases`). Тот же подход для нового компонента.

## Вывод 1: Bot API и URL-кнопки

Источник: официальная документация <https://core.telegram.org/bots/api>, объект `InlineKeyboardButton`, поле `url`:

> «Optional. HTTP or tg:// URL to be opened when the button is pressed. Links tg://user?id=<user_id> can be used to mention a user by their identifier without using a username, if this is allowed by their privacy settings.»

То есть допустимы только `http(s)://` и `tg://`; схемы `happ://`, `v2raytun://`, `hiddify://` в URL-кнопку передать нельзя. Предположение владельца подтверждено: нужна https-страница-прослойка.

Не подтверждено документацией: максимальная длина URL кнопки (в Bot API не указана; на практике Telegram ограничивает URL порядка 2048 символов) и точный набор причин `BUTTON_URL_INVALID` (известно со слов владельца: нужен https и хост с точкой). Поэтому: (а) валидация адреса страницы при старте по правилу владельца, (б) защитный предел длины URL кнопки, (в) повторная отправка без кнопок при отказе Telegram (иначе сообщение со ссылкой подписки не дойдёт - особенно критично для первой покупки, где заказ уже завершён).

## Decision 1: структура страницы и тестируемость

- Один файл `web/connect/index.html`. Вся логика проверки - чистые функции в помеченном блоке `/* LOGIC:BEGIN */ ... /* LOGIC:END */` внутри единственного `<script>`; работа с DOM - ниже, отдельно.
- Тест на Node (`node:test`, встроенный, без зависимостей): читает `index.html`, вырезает блок между маркерами и выполняет через `new Function` - проверяет **тот же код**, который работает в браузере (дублирования нет, расхождения невозможны). Node v24 на машине есть.
- Дополнительные статические проверки файла: нет `innerHTML`/`outerHTML`/`document.write`/`eval`/`new Function` в самом файле, нет `src=`, `<link`, `@import`, `url(`, `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`; `ALLOWED_SUB_HOSTS` в репозитории пуст.
- Обёртка `tests/test_connect_page.py` запускает `node --test` через `subprocess` и пропускается (skip), если Node не найден, чтобы общий `pytest` проверял и страницу.

## Decision 2: правила валидации на странице

- `app`: только собственные ключи таблицы `APPS` (`Object.prototype.hasOwnProperty`), чтобы `__proto__`/`constructor` не проходили.
- `sub`: строка до 2048 символов без пробелов/управляющих символов; `new URL()`; `protocol === 'https:'`; без `username`/`password`; без `hash`; `hostname` (нижний регистр) **точно** входит в `ALLOWED_SUB_HOSTS` (суффиксов нет: `evil-example.com` и `example.com.evil.net` не проходят); порт не ограничивается (панель может работать на нестандартном порту). Пустой список = отказ. Для deeplink используется нормализованный `url.href`.
- Ошибки не раскрывают причину (нейтральный текст).
- Deeplink собирается только из шаблонов `APPS`; перед переходом проверяется префикс схемы из белого списка.

## Decision 3: бот

- Чистая функция `build_connect_url(config, app, sub_url)` и валидация `parse_connect_config` в `src/domain/connect_links.py` (без зависимостей).
- Адаптер `src/adapters/tg_bot/connect.py`: `ConnectKeyboard` (отдаёт строки кнопок, пустой список при выключенной фиче) и функция отправки с повтором без кнопок при `BadRequest`.
- `AdminUseCases` получает необязательный `connect_keyboard=None` (существующие тесты не меняются; без него поведение прежнее).
- В логи - только факт показа кнопок и число кнопок; предупреждения конфигурации не содержат URL подписки (адрес страницы в предупреждениях допустим только без фрагмента: он в конфиге не содержит секретов).

## Decision 4: тексты

- С кнопками: «Нажмите кнопку своего приложения - подписка добавится автоматически. Если приложение не открылось, скопируйте ссылку и добавьте её вручную.» Без кнопок - прежние тексты (инструкция по Happ).
- Подписи кнопок: «Подключить в Happ», «Подключить в V2RayTun», «Подключить в Hiddify» (по одной в строке).

## Риски

1. `happ://add/` и `v2raytun://import/` не подтверждены официальной документацией - проверка на устройствах за владельцем; схемы изолированы в одной таблице.
2. Отказ Telegram по кнопкам может потерять сообщение со ссылкой - закрыто повтором без кнопок (тест).
3. iOS/встроенный браузер Telegram могут блокировать автопереход - есть кнопка с жестом пользователя и подсказка.
4. Токен подписки остаётся в истории браузера пользователя (фрагмент не уходит на сервер, но хранится в истории устройства). Очистка адресной строки через `history.replaceState` не делается, чтобы кнопка и перезагрузка страницы работали; можно добавить по желанию.
5. `ALLOWED_SUB_HOSTS` пуст по умолчанию: пока владелец не пропишет хост при деплое, страница всем отказывает (намеренно).
