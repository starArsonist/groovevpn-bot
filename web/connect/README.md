# Страница подключения подписки в один тап

Статичная страница-прослойка. Кнопки бота («Подключить в Happ» и т.п.) ведут сюда, а страница открывает приложение и добавляет подписку. Bot API принимает в URL-кнопках только `http(s)://` и `tg://` (документация `InlineKeyboardButton.url`), поэтому прямая кнопка со схемой `happ://` невозможна.

Один самодостаточный файл `index.html`: без внешних запросов (CDN, шрифты, аналитика, внешние скрипты), без сборки.

## Как работает

```text
бот: https://<страница>/#app=happ&sub=<percent-encoded URL подписки>
страница: проверка -> deeplink -> приложение
```

- Данные во **фрагменте** (`#...`): он не отправляется на сервер, токен подписки не попадает в логи хостинга.
- Страница принимает `app` только из белого списка (`happ`, `v2raytun`, `hiddify`) и `sub` только как https-URL (без учётных данных и фрагмента) с хостом из `ALLOWED_SUB_HOSTS`. Иначе - нейтральная ошибка без редиректа.
- Всё из фрагмента выводится только через `textContent`/DOM API; переход выполняется только на схемы `happ://`, `v2raytun://`, `hiddify://`, собранные по шаблону приложения.
- После загрузки страница через 0,7 с пробует открыть приложение и показывает крупную кнопку «Открыть в ...» (на iOS автопереход без нажатия может блокироваться), кнопку «Скопировать ссылку подписки» и подсказку.

## Деплой (вы делаете сами)

1. **Хост подписки**: откройте `index.html` и впишите хост(ы) ссылок подписки в начале скрипта:

   ```js
   const ALLOWED_SUB_HOSTS = ['sub.example.com'];
   ```

   Только имя хоста (без схемы и порта), точное совпадение, регистр не важен. Какой хост у вас: тот, что стоит в `subscription_url` пользователей Marzban (например, у панели с портом `...:8443` в список идёт только имя хоста, порт указывать не нужно). **Пока список пуст, страница всем отказывает** - так задумано.
2. **Имя профиля Hiddify**: `PROFILE_NAME` (по умолчанию `Groove`).
3. **Раздача**: как статика по **https** на домене с точкой в имени (Telegram отклоняет кнопки с другими адресами: `BUTTON_URL_INVALID`).
4. **Заголовки ответа** (в конфиге веб-сервера/CDN):

   ```text
   X-Robots-Tag: noindex
   Referrer-Policy: no-referrer
   ```

   В самом файле уже есть `<meta name="referrer" content="no-referrer">`, `<meta name="robots" content="noindex,nofollow">` и CSP-мета (`default-src 'none'`), заголовки - дополнительная защита.
5. **Бот**: в `.env` пропишите адрес страницы и (по желанию) порядок кнопок:

   ```env
   CONNECT_PAGE_URL=https://connect.example.com/
   CONNECT_APPS=happ,v2raytun,hiddify
   ```

   Пустое или невалидное значение (не https, хост без точки) - кнопки не показываются, бот работает как раньше, в логе предупреждение.

## Тесты

```bash
node --test web/connect/validate.test.mjs
```

Тест выполняет тот же блок `LOGIC:BEGIN/END` из `index.html`, что работает в браузере (без зависимостей), и проверяет файл статически: нет небезопасных DOM-API, нет внешних загрузок, `ALLOWED_SUB_HOSTS` пуст в репозитории. Из `pytest` этот тест запускается обёрткой `tests/test_connect_page.py` (пропускается, если Node не найден).

## Источники

**Схемы приложений** (шаблоны собираются в таблице `APPS` внутри `index.html`):

| Приложение | Схема | Подтверждение |
|------------|-------|---------------|
| Hiddify | `hiddify://import/<sub>#<имя>` | Официально: <https://hiddify.com/app/URL-Scheme/> |
| Happ | `happ://add/<sub>` | Со слов владельца. Официальный FAQ <https://www.happ.su/main/faq/adding-configuration-subscription.md> подтверждает добавление подписки через deeplink, но синтаксис `happ://add/...` в просмотренной документации не найден. **Проверить на устройствах** |
| V2RayTun | `v2raytun://import/<sub>` | Со слов владельца, официальной документации найти не удалось. **Проверить на устройствах** |

**Ссылки «Где скачать»** (только официальные страницы приложений):

| Приложение | Ссылка | Источник |
|------------|--------|----------|
| Happ | <https://www.happ.su/main> | Официальный сайт Happ (на нём ссылки на App Store, Google Play и релизы) |
| Hiddify | <https://hiddify.com/app/> | Официальная страница приложения Hiddify (раздел «Get Hiddify app» по платформам) |
| V2RayTun | нет | Официальную страницу подтвердить не удалось - ссылка намеренно не добавлена |

## Чек-лист ручной проверки на устройствах

Проверьте после деплоя (и после заполнения `ALLOWED_SUB_HOSTS`). Логика валидации покрыта автотестами, но поведение приложений и браузеров - только на устройствах.

- [ ] iOS: Safari и Happ/V2RayTun/Hiddify - кнопка «Открыть в ...» запускает приложение и добавляет подписку (автопереход может блокироваться - это нормально, кнопка должна работать).
- [ ] Android: Chrome и те же приложения.
- [ ] Windows и macOS: браузер и десктопные версии приложений.
- [ ] Встроенный браузер Telegram: открывается ли приложение; если нет - подсказка «откройте в браузере через меню ⋯» понятна и после открытия в браузере всё работает.
- [ ] Допустимый хост: подписка добавилась, имя профиля Hiddify - `Groove`.
- [ ] Чужой хост подписки (подмените `sub` в адресе): страница показывает нейтральную ошибку, ничего не открывается.
- [ ] Неизвестное приложение (`#app=evil&sub=...`): ошибка.
- [ ] Пустой фрагмент (адрес страницы без `#...`): ошибка.
- [ ] Подстановка `javascript:` или `http://` в `sub`: ошибка, редиректа нет.
- [ ] «Скопировать ссылку подписки»: ссылка попадает в буфер (на iOS/Android и в Telegram-браузере; если нет - ссылка под кнопкой выделяется целиком по нажатию).
- [ ] Светлая и тёмная тема переключаются по системной настройке.
- [ ] В логах хостинга нет токена подписки (проверьте access-лог: в запросах только путь страницы).
